# SRC-INTERVIEW-001 — 浏览器 MCP 需求访谈

时间: 2026-08-08
受访者: 用户(需求提出人)
记录: requirements-coordinator

## 访谈记录

### Q1. 使用场景
**用户回答**: "应该是1(指 AI Agent 自动浏览),同时为还希望它可以和按钮互动,比如提交到按钮里面一个信息,下载表单的那个信息。也就是说要需要具备上传和下载的能力。"

- 类型: DECISION / OBSERVED_FACT
- 结论:
  - 核心用户: AI Agent(LLM 驱动自动浏览)
  - 需要交互: 不仅读页面,还要能操作按钮
  - 需要上传: 向表单/按钮提交信息
  - 需要下载: 从页面下载数据/表单信息

### Q2. 读取目标程度
**用户回答**: "读+点击交互"

- 类型: DECISION
- 结论: 在读取页面+按钮元数据基础上,需要点击交互能力

### Q3. 部署形态
**用户回答**: "待定/需要分析"

- 类型: OPEN_QUESTION
- 结论: 部署形态(本机 MCP vs 远端主机 vs Docker)尚未决定,需要架构分析支撑

## 证据分级
- Q1 核心是需求方向(DECISION),具体上传/下载的形态还需细化
- Q3 是 OPEN_QUESTION,需要在 CURRENT_STATE / TECH 阶段分析

### Q4. 目标站点类型
**用户回答**: "两种都要"

- 类型: DECISION
- 结论: 公开网站和需登录的内部系统都要支持 → 需要登录态/cookie/认证管理

### Q5. 浏览器运行形态
**用户回答**: "需要建议"

- 类型: OPEN_QUESTION
- 结论: 需要架构分析给出建议(本机 Playwright vs 远端 CDP vs 容器服务)

### Q6. 按钮信息字段
**用户回答**: text 文本 / selector 选择器 / 位置可见性 / aria状态属性(全选)

- 类型: DECISION
- 结论: 按钮信息 = text + selector + 位置/尺寸/可见性/可点击性 + aria/role/disabled
